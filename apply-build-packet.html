1. High-level overview

The apply site at apply.thecolyerteam.com is a public-facing, single-page, 9-step mortgage loan application built as a static HTML/CSS/JS file hosted on Netlify. It collects borrower information for purchase, refinance, or cash-out refinance loans and submits directly to the Supabase loan_applications table via the PostgREST API using the anon role. On insert, five database triggers fire in sequence: validate_loan_application (server-side field validation + rate limiting), fn_client_on_loan_application (deduplicate or create a clients record), fn_lead_on_loan_application (upsert into leads table with state promotion), fn_log_web_app_submission (write to loan_activity_log), fn_drip_auto_switch_on_loan_app (switch active drip campaigns to application-stage campaigns), and notify_loan_application (HTTP call via pg_net to the webhook server for confirmation + notification emails). The resulting record is visible in the LOS at los.thecolyerteam.com (branded as thelenderreport.com).

3. Behavior and validation

Client-side validation (per step)

  • Step 1: Loan Purpose and Property Type radio selections required (alert dialog if missing)
  • Steps 2–6, 9: All fields with <span class="req">*</span> in label are validated:
  • Empty → invalid class + inline error message
  • data-min attribute enforces minimum character length
  • Email: regex ^[^\s@]+@[^\s@]+\.[^\s@]+$
  • Phone: 10-11 digits after stripping non-numeric
  • SSN: exactly 9 digits after stripping
  • ZIP: exactly 5 digits (/^\d{5}$/)
  • Step 9 (submit): Both consent checkboxes required, e-signature non-empty
  • Step 7 (declarations): No validation enforced — answers can be left "Unanswered"
  • Step 8 (documents): No validation — entirely optional

Input formatting (auto)

  • Currency fields (inputmode="numeric"): On blur → $N,NNN; on focus → strip to digits
  • Phone: Auto-formats to (XXX) XXX-XXXX
  • SSN: Auto-formats to XXX-XX-XXXX (password field, masked)
  • DOB: Auto-formats to MM/DD/YYYY with auto-slashes

Bot protection

  1. Honeypot field (#ohnohoney): hidden input; if filled, submit silently aborts
  2. Timestamp check: formLoadTime recorded on page load; submit blocked if elapsed < 10 seconds ("Please take a moment to review your application.")
  3. Cloudflare Turnstile widget (sitekey 0x4AAAAAACciFKo0RiY3gv0u): token captured but ⚠️ NOT verified client-side before submit — server-side verification happens in the webhook server (non-blocking; logs failure but does not reject)

Server-side validation (DB trigger: validate_loan_application)

  • first_name ≥ 2 chars
  • last_name ≥ 2 chars
  • email matches ^[^@]+@[^@]+\.[^@]+$
  • phone ≥ 10 digits (stripped)

4. Data flow into LOS

Submission path

  1. Client JS collects all form data into a flat JSON object
  2. POST to https://apuctuqlmykeemtcasji.supabase.co/rest/v1/loan_applications
  3. Auth: Supabase anon key (both apikey and Authorization headers)
  4. Header: Prefer: return=minimal
  5. Supabase RLS allows anon insert (insert-only policy)

DB trigger chain (BEFORE INSERT / AFTER INSERT)

Order Trigger Function Type What it does
1 trg_validate_loan_application validate_loan_application BEFORE INSERT Validates name, email, phone; rate-limits 3/email/24h
2 trg_client_on_loan_application fn_client_on_loan_application BEFORE INSERT Dedupes by email → phone → creates new clients row; sets NEW.client_id and NEW.intake_log
3 trg_lead_on_loan_application fn_lead_on_loan_application AFTER INSERT Upserts leads row; promotes state to app_sent if currently below that level; sets loan_application_id and client_id
4 trg_log_web_app_submission fn_log_web_app_submission AFTER INSERT Inserts loan_activity_log entry: type web_app_submitted
5 trg_drip_auto_switch_on_loan_app fn_drip_auto_switch_on_loan_app AFTER INSERT Completes active "Referral - No Contact Yet" or "Post First Contact" drip enrollments; re-enrolls into purchase or refi application campaign
6 trg_notify_loan_application notify_loan_application AFTER INSERT Calls pg_net.http_post to webhook server /api/loan-notification

Webhook server (loan-webhook-server.py on port 8899)

Receives the notification POST at /api/loan-notification and:

  1. Optionally verifies Turnstile token (non-blocking)
  2. Sends confirmation email to borrower via MS Graph (ms-graph.py send)
  3. Sends notification email to Mike (mike@thecolyerteam.com) with application summary
  4. PATCHes confirmation_sent = true on the loan_applications row

Final state of a typical new record

loan_applications: - id: auto UUID - status: 'new' - pipeline_stage: 'new_application' - loan_officer_id: Mike's UUID - client_id: set by trigger (matched or newly created) - intake_log: JSON with match_type, client_id, action, is_past_client - confirmation_sent: true (after webhook) - created_at / updated_at: now()

clients: Either existing record matched (by email or phone) or new row with first_name, last_name, email, phone, segment 'past_client' (default).

leads: Upserted with state = 'app_sent' (if previously lower), source = 'web_form', lead_type = 'contact', jurisdiction set from property state (CA/WA or 'unknown').

loan_activity_log: One row: activity_type = 'web_app_submitted', performed_by = 'system', metadata includes source, loan_purpose, client_id, intake_log.

Known limitations

  • Co-borrower stored as a single JSONB blob — no separate DB columns, no dedicated co-borrower table
  • Documents are metadata only (name/size/type) — actual files are never uploaded; the documents column just records what the borrower intended to upload
  • SSN reduced to last 4 digits before transmission — full SSN never leaves the browser
  • Previous address/employer fields: city/state/zip and title/years/income are collected on-screen but not included in the submit payload
  • Other Real Estate sent as raw string to a text column (not parsed to numeric)
  • Turnstile token is sent in the payload as cf_turnstile_response but there's no matching column in the DB — it's silently dropped by Supabase or causes a non-fatal issue
  • Page view tracking: a separate POST to page_views table fires on page load (page='apply', referrer, user_agent)

6. Design & UX notes

Layout

  • Single-page, multi-step wizard (9 steps) inside a centered white card (max-width 720px)
  • One step visible at a time; CSS display:none / display:block toggle
  • Form fields in 1-, 2-, or 3-column grids depending on field type
  • Mobile responsive at 600px breakpoint: all grids collapse to single column

Progress indicator

  • Numbered step indicators (1–9) across top, with active (red) / done (gray-600) / future (gray-400) styling
  • Gradient progress bar (red) showing percentage width (currentStep / 9 * 100%)
  • Smooth transition animation on bar width

UX patterns

  • No save-and-resume — if the borrower leaves, all progress is lost
  • No browser back-button handling — only in-form Back/Continue buttons
  • Scroll to top on each step change (window.scrollTo({top:0, behavior:'smooth'}))
  • Option cards (radio selections) use visual card UI with emoji icons and highlight on selection
  • Declaration questions use Yes/No toggle buttons with highlight state
  • Review step auto-generates a summary table from all collected values (SSN masked to ***-**-XXXX)

Typography & color

  • Font: Inter (Google Fonts), system-ui fallback
  • Brand color: #CF202B (red) used for accents, buttons, active states, progress bar
  • Background: #f5f5f5; card: white with large box-shadow

Bot protection

  1. CSS-hidden honeypot field (class="ohnohoney")
  2. Timestamp-based speed check (< 10 seconds = bot)
  3. Cloudflare Turnstile invisible challenge widget

# Issue Severity

10 New clients default to segment = 'past_client' — the clients table default is 'past_client' which is incorrect for brand-new applicants Functional
11 Co-borrower as JSONB blob — not queryable, not visible in LOS pipeline views without special handling UX clarity
12 DOB stored as text, not date — the dob column is text type, preventing date operations Functional
13 years_at_address and years_employed stored as text — should be integer/numeric for queries Functional
